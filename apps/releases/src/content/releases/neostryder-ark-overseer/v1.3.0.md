### Added

- [Visible] [UI] [Settings] **A start, stop, or restart can buzz or chime when it works or fails.** The Feedback on this device card on the Account page has a switch for a short vibration, on by default, and another for a soft tone, off by default. Turning either one on plays it once as a check. The choices are saved in that browser only, and a browser that can't vibrate, such as Safari on an iPhone, skips the vibration.
- [Visible] [Settings] [Server] **Phones and computers can get ARK Overseer alerts through the browser's own push service, end to end encrypted and with no account or outside service to set up.** The Alerts on this device card on the Account page turns them on for that device, lets you pick crash alerts (including when the crash guard stops restarting a server), alerts for new ARK server builds on a watched branch, or both, and sends a test. Tapping an alert opens the server or the This computer page, a server that keeps crashing sends at most one alert every 10 minutes, and on an iPhone or iPad alerts work only from the Home Screen app on iOS 16.4 or later.
- [Visible] [UI] **The browser tab shows when a server needs attention.** Each server that has crashed or been held back by the crash guard adds to a count at the front of the tab title, so two of them read "(2) Overseer", and a red dot appears in the corner of the tab icon. A stopped server doesn't count, and neither does one that is starting or stopping. The count and the dot go away once no server needs attention.
- [Visible] [UI] **Drag down from the top of a page on a phone or tablet to refresh it.** A pill slides in reading "Pull to refresh" and changes to "Release to refresh" once the drag goes far enough. Letting go reloads the server list and the open page, and the pill shows "Refreshing" until the new data arrives. Nothing happens while the menu or a dialog is open, or while the Settings or setup form has unsaved changes. Drags that start in a form field or the Jobs panel don't count.
- [Visible] [UI] **A page that is still loading shows a shimmering placeholder card instead of the word Loading.** Screen readers still announce the Loading label. On a device set to reduce motion, the card sits still.
- [Visible] [Mods] [Server] **A mod id in a server's mod list can end in -dev to load the mod's unpublished test build.** ARK Overseer passes the id to the server as written, for example `-mods=1234567-dev,891011`. Wildcard's unpublished-build testing uses that suffix to make a dedicated server load the mod author's test build instead of the published one, and everyone who joins needs access to that build in their My Mods list. A -dev mod's maps don't appear on the Maps page, since map discovery reads published mod folders only.
- [Visible] [Mods] [Server] **Edit a server's mod list on its Maps page.** The Mods card lists the server's mod ids in load order, which is the order they go into the -mods launch flag. You can add an id, remove one, move one up or down, and save. An id ending in -dev loads that mod's unpublished test build. A mod can appear only once, so a published id and its -dev build can't both be on the list. Saving while the server runs works, and the new list loads at the next start. You can't save while a map switch, backup, or restore is running on that server. Every save is recorded in the audit log. The Active Mods field on the Settings page is now read-only and points to the Maps page. Scripts can make the same change with `PUT /api/servers/:id/mods` and a `mods` array, behind the usual sign-in.

### Changed

- [Visible] [UI] **Start, Stop, and Restart on a server's Overview page change the status right away.** As soon as the button is pressed, the status reads Starting or Stopping, without waiting for the server to answer. If the request fails, the real status comes back along with the error message.
- [Visible] [UI] [Server] **Server status changes show up within a fraction of a second.** Open pages used to ask ARK Overseer for the server list every 5 seconds. ARK Overseer now sends a short notice over a live connection whenever a server starts, stops, or crashes, a job starts or finishes, or anyone saves a change, and each open page fetches the list at that moment. Changes made from another phone or computer appear just as fast, and an idle page makes far fewer requests. If the connection drops, the page checks every 5 seconds until it comes back, and it also refreshes when you return to its tab. The Jobs panel already used a live connection and works as before. Scripts can listen on `GET /api/servers/events`, behind the usual sign-in.
- [Visible] [Server] **The Edge update channel now refreshes only when someone starts the Edge workflow by hand from the GitHub Actions page.** Pushes to the main branch on GitHub no longer rebuild it, so the Edge build can be older than the latest commit. You can still pick Edge on the This computer page next to Stable and Beta, and the Update button installs whichever Edge build is currently published. Stable and Beta still come from version tags.

### Fixed

- [Visible] [Server] **After an update, the new version shows up on the next page load, even behind Cloudflare.** When ARK Overseer was reached through a CDN such as Cloudflare, the CDN kept its own copies of the page scripts and styles, and a browser could run the old ones for up to four hours. ARK Overseer's pages, scripts, styles, and fonts are now marked private, which keeps a CDN from storing them, and the browser checks for a newer copy each time it loads one.
