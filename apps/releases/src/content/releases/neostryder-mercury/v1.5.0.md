### Added

- [Visible] [Pipeline] **Mercury now builds rule proposals through the judge's long background call, so slow instruction turns no longer die at the gateway timeout.** Proposals from the Thunderbird flag popup and Telegram replies to a proposal run in a background task, yet they called the judge's blocking `ask`, which the gateway ends with a 504 near 290 seconds; an instruction turn that needed about 8 minutes on 2026-11-19 failed twice and produced only an error message. The proposal task now waits on `ask_long` for up to 1620 seconds, falls back to `ask` when the judge has no long call, and retries once after a transport error or a 502, 503, or 504 response, while a reply the judge reports as failed or a job that never answers gets no retry. The ingest path does not use this call, because it must answer the mail host quickly (#137).
- [Visible] [Thunderbird] **The Thunderbird flag popup no longer reports a failure while a rule proposal is still being built.** Previously, `/rules/propose` built the proposal while the request stayed open, and the judge's agent turn can take several minutes, so Cloudflare closed the connection after 100 seconds, the popup stayed on "Sending..." and then reported a failure, and the proposal could still arrive on Telegram afterward. The endpoint now checks the secret, reads the instruction and the attached messages, answers `{"ok": true, "status": "queued"}` at once, and builds the proposal in a background task that sends it to Telegram for approval, with any failure in that task still sent to the notifier as "Mercury rule-proposal error" and logged. After a queued answer the popup shows "Sent to Mercury. The proposal will arrive on Telegram when it is ready.", and when the server answers with something that is not JSON it shows the HTTP status instead of a parse error and re-enables the Send button. The response no longer carries the `rule` and `action` fields, and older popups keep working because they show "Sent to Mercury." when neither field comes back (#137).
- [Visible] [Pipeline] **The `judge_unavailable_for_review` event now records how the language-model judge failed and how long the call ran, and the judge prompt sets a time budget.** The event lists the exception type, the HTTP status code when the failure is an HTTP error, and the seconds elapsed since the call began (for example `HTTPStatusError status=504 elapsed=287.4s`), and the event for an unreadable reply records elapsed seconds too. Previously the event recorded only the exception type, so a timeout, a 504, and a refused connection looked the same. The prompt for this review now gives the judge a budget of about 150 seconds (`JUDGE_REVIEW_BUDGET_SECONDS` in `backend/app.py`) and tells it to abandon a web lookup that stalls or times out and to answer in the required format from the evidence it already has instead of retrying. The wait for the judge is unchanged because the mail host waits on the verdict, and the message's reasoning still says the classifier decided alone (#133).
- [Visible] [Filtering] **Mercury now delivers a message the classifier would reject when the judge returns LEGIT with disposition 250 and the sender passes the authentication and injection checks.** Previously a classifier reject overruled by the judge stayed held at 421 unless the judge quoted one of the recipient's standing accept rules word for word (issue 88), and judges that reasoned correctly without copying a rule left genuine mail held: a review of 38 held messages on 2026-11-14 found about 20 genuine ones, including Walmart pickup and delivery notices, a payment-platform sign-in alert, a tax-software renewal notice, and credit-bureau and HSA notices. The LEGIT path delivers only when the sender passes DMARC aligned with its From domain, the injection screen says SAFE, and the classifier's credential-or-payment and injection signals are below their thresholds, and any one condition failing keeps the hold. The reasoning line names whether the rule path or the LEGIT path delivered the message. The judge also receives the computed sender domain, how the recipient was addressed, and whether the merchant name in an rpgm.tools alias (such as `aaron-walmart@rpgm.tools`) appears in a label of the sender's domain, without the address itself.
- [Visible] [Pipeline] **Mercury now logs a `judge_unavailable_for_review` event when the language-model judge gives no usable answer.** Previously, if the judge could not be reached or answered without a usable verdict and an explicit disposition line, Mercury kept the classifier's decision silently, so a genuine message could be held with no judge opinion and no trace. The event now goes to the admin log, and the message's reasoning gets a sentence saying the classifier decided alone.
- [Visible] [Pipeline] **Mercury now strips padding and hidden html from what the classifier and judge read, and the daily digest guard keeps sentences where a negation comes before the claim word.** Genuine marketing and notice mail used to reach the judges looking blank or truncated and was deferred as UNSURE, and the digest guard dropped a compliant sentence because it saw the word explaining inside "without explaining". The judges' input now has invisible padding characters such as soft hyphens and byte order marks removed, along with hidden html such as display:none, and a plain text part counts as a stub by words (40 or fewer next to html with three times as many) instead of by characters. URLs over 160 characters are shortened to host plus a short path for the classifier and judge only, so the saved content and link filter still see the full URL, and content that still exceeds the window (4000 characters for the classifier, 6000 for the judge) is cut at a word boundary and ends with a [Content truncated] marker. The digest guard now ignores a claim word when a negation cue such as no, not, never, without, or cannot sits in the same clause within the five words before it, while a claim after a comma, "but", or "however" is still dropped.
- [Visible] [Pipeline] **Mercury now checks the digest's insights paragraph against all six sentence kinds its prompt forbids, up from two.** The old check caught rankings of counters and claimed relationships between them, so trend claims, inferred causes, maintenance advice, and restated figures reached the email unchecked. A sentence now gets dropped when it describes a change over time ("spiked", "up from yesterday", "than usual"), names a reason ("stems from", "attributable to"), or gives advice ("should", "consider", "prune"). It also gets dropped when it repeats two or more figures the digest already shows, such as the message count, hard bounces, or verdict counts, with 0 and 1 ignored. The remaining sentences stay. If none are left, the digest uses a plain paragraph built from the statistics. A sentence that mentions no counter passes untouched, as does "nothing unusual stands out." The backend log records each dropped sentence with its reason, for example "trend claim" or "restatement of the tables." Pull and rebuild the backend container to pick this up.
- [Visible] [Pipeline] **Mercury reaches the prompt-injection classifier and Laya through the Cogitator gateway, which fails over between nodes.** Both checks used to call one engine port on one node (port 8009 for the classifier, 8010 for Laya), and on 2026-11-09 the classifier check failed with a connection error when Bilbo's classifier did not come back after a restart. COGITATOR_GATEWAY_URLS lists the gateway base URLs in the order to try them, and COGITATOR_MERCURY_KEY is sent as a bearer token. A connection error, a timeout, a 5xx answer, or a 401, 403, or 404 from a gateway moves to the next endpoint. The direct URLs in PROMPT_INJECTION_CLASSIFIER_URL and LAYA_URL stay last in the list, and PROMPT_INJECTION_CLASSIFIER_URL now accepts several comma-separated URLs. A failed endpoint is skipped for 30 seconds unless every endpoint has failed. When every endpoint fails, the classifier raises the last error and the same alert fires. With either setting empty, only the direct URLs are used. To pick this up, set both values in the backend .env, then pull and rebuild the backend container.
- [Visible] [Pipeline] **Mercury now keeps held (421) and rejected (550) messages for 30 days so corrections on the Review page can train the classifiers.** Their text used to be discarded, so a correction on the dashboard Review page could not become training data, even though the 38 held messages reviewed on 2026-11-14 included about 20 genuine ones. The backend stores the redacted text, computed sender facts, and the structured classifier's raw answers on its own host, outside the dashboard database, and stores nothing for accepted messages or for messages whose text is already gone. Marking a message right or wrong on the Review page makes its row permanent and records the intended outcome (deliver, block as spam or phishing, or hold), undo clears it, and the page shows how many rows are labeled and how many held messages are kept. Labeled rows export in the Laya import format (pilot mercury_screen) from the new Download training rows link to train the local Laya model, because hosted Jev cannot be trained, and they also guide the wording of the classifier questions and rules.
