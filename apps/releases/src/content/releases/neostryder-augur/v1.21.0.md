### Added

- [Visible] [Platform] **Ledger changes stream over HTTP, and the ledger records sessions.** `GET /api/dispatch/changes` sends ledger changes as newline-delimited JSON to local programs that hold the owner token, and the browser app now refreshes when a change arrives instead of polling every three seconds. It polls only while the stream is down. A new `sessions` channel records when the service first sees a session id on a job and when that session's title changes, and `ledger_changes` takes a `channel` argument that defaults to `jobs`. `jobs-live.json` adds the ledger's `cursor` and the `sessions` rows, which the Claude Code pane does not draw.
- [Visible] [UI] **Live jobs button above the prompt.** In the Claude Code and Claude Desktop mod, the row above the prompt always shows one slim line with "Augur", the number of live and closed jobs across all sessions, an "Augur live jobs" button (hotkey j), and the Open Augur button (hotkey o). The button opens the augur-jobs pane in any session that has the mod at any window width, while before the pane opened by itself only after the session started live jobs and often did not appear because Claude does not place a self-opening pane in a window narrower than 144 columns. The augur-jobs command still works, the same button sits in the alert row before Dismiss when an alert is showing, and a survey still takes over the row without the line drawing over it.
- [Visible] [UI] **Running version in the Usage header.** The Usage page header shows the version the desktop app reports as its own, such as 1.21.0-edge.119, in small muted text beside the title, and hovering it shows "Version 1.21.0-edge.119". A host that cannot report a version, such as the browser app served by the service when the shell gives none, shows nothing there.
- [Visible] [Providers] **The OpenAI API card shows project spend and a 7-day strip from the Usage page.** With "Read OpenAI billing page" on, Augur reads the platform.openai.com Usage page for the project selected in its filters and shows daily spend plus request and token totals for the last 7 days. Accounts without billing permission get these figures too.
- [Visible] [UI] **The Usage page hides money rows whose amount is zero.** Meters, errors, and sign-in notes still show, and the Show hidden rows checkbox (h in the terminal screen) brings the zero rows back and saves the choice.
- [Visible] [Providers] **Grok jobs that end without their expected file are resumed.** A Grok job run with `--expect-file` (MCP `expectFile`) that ends its turn without the file is resumed in the same Grok session up to 2 times, each time as a new job linked to the first, with a note to wait for background work using a blocking command and write the file. Jobs started in a named conversation or without a session id are not resumed, and after two resumes without the file the last job stays `artifact_validation_failed`.
- [Visible] [Providers] The new `claude-exec` adapter runs Claude Code (`claude -p`) on an Anthropic API key, so a route can give a Claude model tools and bill the API key instead of a subscription. Read jobs get Read, Grep, and Glob only. Write and full jobs approve every tool, and the none tier disables built-in tools. A small wrapper reads the stored key when the job starts, so the key never reaches the service or a job file. Every job passes a turn cap (default 40, range 1 to 500) and a dollar cap (default $2, up to $50). A job that hits either cap fails and does not hold the route as a spent allowance. Profile context is trimmed with `--bare` unless the route's `ambient` is `keep`. Named conversations resume with a session id. The configuration reference lists the route options.
- [Visible] [Providers] An `openai-api` route with Request type `images` now runs `generate_images` and `image_to_image` jobs and saves each result in the job's folder as image-1.png, image-2.png, and so on, with example routes openai-image-fast and openai-image-quality.
- [Visible] [UI] The Usage page and Settings have an OpenAI API card that shows calls, tokens, images, and estimated cost for jobs on `openai-api` routes, and it can read prepaid credit, promotional credit, and the month's spend from the platform.openai.com billing page after you sign in.
- [Visible] [Platform] Added the "Slots kept for quick jobs" setting (`quickSlots`, default 2) to hold job slots back from long jobs such as Codex runs and web chats, so quick API jobs no longer wait up to 30 minutes behind them. Set it to 0 to turn the reservation off.
- [Visible] [UI] The `augur-jobs` pane draws each job as a card with colored `ORIGIN:`, `JOB:`, and `ACTIVITY:` or `RESULT:` lines, starts on this session's jobs with `f` to switch to every session, lists the last 30 ended jobs in a collapsed CLOSED section that `c` opens, and opens by itself only for this session's live jobs.
- [Visible] [UI] Live cards in the augur-jobs pane have a Cancel job button that needs a second press and writes to `cancel-requests.jsonl`, which augurd reads to cancel the job, and the pane has an Open Augur button (hotkey `a`) that starts the app.
- [Visible] [Providers] Prompts on claude-api routes gained a `<!-- augur:cache-break -->` line: the text above it is sent as a cached system block that later jobs starting with the same text read at the cache-read price instead of the full input price, the text below it plus any attached files is the job, and a prompt without the line is sent as before. A new route option `cacheTtl` was added to set how long the provider keeps the cached text, either `5m` (default, 1.25 times the input price to write) or `1h` (2 times), and caching needs at least 512 tokens above the line on Opus 5.5, Sonnet 5.5, and Haiku 5.5.
- [Visible] [Providers] Claude API in settings gained a "Read credit from the Console" switch and a Sign in button that read prepaid credit, each promotional credit grant with its end date, and this month's spend from the Claude Console billing page (platform.claude.com), using a session kept in Augur's own window and read at most every 30 minutes, because the Admin API cannot supply these figures for a personal organization. The usage view gained an "of promotional credit ends <date>" note for the grant that ends first.
- [Visible] [Platform] `python train.py promote` now compares accuracy and calibration for the new and live adapters on the same test rows, where it used to compare exact-match accuracy alone with NLL breaking ties. The new adapter replaces the live one only when at least one question wins and none loses. A question wins when exact accuracy rises by at least `--margin` (default 0.03), or stays level while Brier score falls by at least `--brier-tol` (default 0.01). It loses when exact accuracy or NLL falls, Brier rises by more than `--brier-tol`, ECE rises by more than `--ece-tol` (default 0.03), or Brier on the newest half of the rows rises by more than twice `--brier-tol` (checked only when that half has 40 or more rows). A question with fewer than `--min-n` (default 300) test rows is reported as underpowered, `--require-n N` makes fewer than N rows a hold, and `--force` still skips the comparison. The printed verdict and the adapter's manifest also show Brier score, risk-coverage area, reliability by confidence bin, recall and mean confidence by true option, and milliseconds per row.
- [Visible] [Platform] **Failed jobs now show why they failed.** `augur job` prints a `Reason:` line under the usage line, and `augur result` prints one before the answer for failed, killed, lost, and artifact-failed jobs. The ledger record gains an optional `failureReason` field, shown in `augur jobs --json` and the MCP `augur_job` tool.
- [Visible] [Platform] A premium label now runs from an automated caller, including the MCP `augur_run` tool, when the owner named it in one of the job session's last three typed messages within the past 360 minutes. The owner hook's `human_prompt` call records the named models, and the job records `named: true` with a `named_claim` event whose source is `prompt`. The agent token still cannot call `human_prompt` or send `named`, `allow`, or `released`, and `augur_pick` from the agent token still never offers a premium label.

### Changed

- [Visible] [UI] **Job cards are colored by state.** Cards on the app's Jobs page and the terminal Jobs screen get a tone from the shared card projection, so a failed, lost, or stalled job stands out before anyone reads its text. Red marks failed, lost, and node lost jobs, green marks completed or done ones, and running or queued jobs are blue. Yellow covers any stalled job whatever its state, along with jobs waiting for approval, being cancelled, cancelled, or killed, and every other state is grey. The app draws the tone as a 3 px left border in both themes, while the terminal screen uses it for the state chip's color.
- [Visible] [UI] **Provider cards move background notes behind an info mark.** On the Usage page, reset counts, sign-in and Cloudflare prompts, the last-7-days request and token line, and the Augur ledger activity line stay on the card, while gated model lists, per-model ledger lines, Codex counts of ChatGPT chat jobs, refill rules and answer times, and the organization billing note appear when you hover or keyboard-focus the small info mark. The gate line still shows Open or Closed and the points behind pace, and the terminal screen still prints every note.
- [Visible] [UI] **Jobs use one card layout in the app, terminal, and Claude Code.** The Jobs page, the Dispatch screen's job list, and the augur-jobs pane now draw each job with the same labeled lines, including new `TIMING:` and `USAGE:` lines that replace the cost and timing the pane used to fold into other lines. The Jobs page and the terminal list start on this session's jobs, with a "This session" / "All sessions" switch (terminal key f) and a collapsed Closed section of the last 30 ended jobs (terminal key c), which the ledger response now carries directly so it does not depend on the loaded history page.
- [Visible] [UI] **The OpenAI API card is shorter and tracks spend against a monthly budget.** The card drops prepaid credit, promotional credit, the Today and Month estimate rows, and the calls-without-a-price line, and it now shows the organization's spend this month, a Monthly budget bar such as "$62.10 of $250", and one activity line from Augur's ledger. The new Monthly budget setting (`monthlyBudgetUsd`) sets the budget and means $250 when left empty.
- [Visible] [UI] **The Claude API card now shows the largest credit grant that has not ended as a Monthly credit bar.** Like the subscription meters, the bar gives the share used, a detail such as "456.27 of 500 left", and the grant's end date as its renewal date, so the card no longer lists the smaller promotional grants and the Usage page drops its "promotional credit ends" note.
- [Visible] [Platform] **Failed Codex, Grok, and mcode jobs now report the engine's own error message as their failure reason.** A failed `codex-exec` job takes its reason from the final error in its Codex session log and keeps `exit N` only when that log is missing or unreadable, so a provider cybersecurity block no longer looks like a crash. Job and ledger records also gain an optional `failureCode`, such as `cyber_policy`, shown in `augur job`, `augur jobs --json`, and the MCP `augur_job` tool. Grok and mcode jobs use the message from their error result, and mcode adds its error code when present.
- [Visible] [Providers] The Routes form saves the Allow web tools choice as true or false, so `allowWeb` on a `claude-exec` route saves as a boolean.
- [Visible] [UI] The Codex card shows how many ChatGPT chat jobs ran through Augur in the last 7 days, since ChatGPT in the browser now draws on the same allowance as Codex. The percentages on the card still come from Codex.
- [Visible] [Platform] With `runner.failover` on, a route whose job fails because the provider reports a spent allowance (rate, usage, or credit limits, quota, too many requests, resource exhausted) is now held for 24 hours: new jobs go straight to the first fallback that is not held, its waiting and running jobs with tools `read` or `none` move there too, and holds persist across restarts in `route-limits.json`.
- [Visible] [Platform] A model a person asked for now runs without Augur re-checking the claim, because `verifyNamed` defaults to `off` (it was `enforce`); set it to `enforce` to keep the check. Premium models are still refused for automated callers.
- [Visible] [Docs] The configuration reference now lists the `provider` route option of `hermes-exec` and explains that the DeepInfra host pin for the deepseek, glm, and mimo models lives in Hermes's own `provider_routing` settings and applies to read jobs only when `readMode` is set to `keep`. SECURITY.md and the engine-file list no longer mention OpenCode or sandboxed harnesses.
- [Visible] [Platform] The desktop app's updater now sets requireSignedVersion, so it installs an update only when the download's signature names the same version the update manifest announces and refuses a manifest that pairs a higher version with an older signed installer. Every published release and early build is already signed with its version, so no existing install loses its update path.
- [Internal] [Security] The Desktop installers workflow accepts a manual run only from main or a version tag, so code on another branch cannot reach the signing key.
- [Internal] [Security] **The relay's wrangler dev dependency moved from 4.141 to 4.158.** Its miniflare 5.20261104.0 beta brings undici 7.30.1 and sharp 0.35.5, replacing copies with 16 open high-severity Dependabot alerts, and the Workers types package moved to 5.20261109.1 to match. Only dev tooling changed: the bundled Worker code, desktop app, and service are unchanged.
- [Visible] [Platform] HTTPS responses the service reads for usage, update, and model-list lookups now stop at 8 MiB, and an API route's reply (chat text or embeddings) stops at 64 MiB and fails the job with "response too large". Laya, while busy and handing a request to another server through LAYA_FAILOVER_URLS, answers 413 for a body over 8 MiB, a limit LAYA_MAX_BODY sets in bytes.
- [Visible] [Platform] In the web chat, one person's uploaded files may total 1024 MB across all their chats (delete a chat that holds files to make room), a single message may hold at most 2 MB of text, and one chat may hold at most 2000 messages (start a new chat to continue).
- [Internal] [Security] When the service cannot limit its owner or agent token file to its owner because chmod or icacls fails, it now writes a warning to standard error naming the file and folder instead of continuing silently. In that case the folder's own access list is the only protection for the token.

### Fixed

- [Visible] [Providers] **Routes that call GPT-6.x models on the OpenAI API, such as gpt-6.2-sol, no longer fail with HTTP 400.** Chat requests to api.openai.com now send the route's maxTokens as max_completion_tokens, so these routes keep their output cap without the old workaround of setting maxTokens to 0. Other OpenAI-compatible hosts (OpenRouter, DeepSeek, MiniMax, local gateways) still receive max_tokens, and a maxTokens of 0 still omits the limit.
- [Visible] [Platform] **The fal video runner now retries after a dropped connection.** `fal-call` repeats status checks, the result, and the video download up to 10 requests in all, waiting 2, 4, 8, 16, 32, then 60 seconds within the job's `timeoutS`, and it resends the submit only when the connection never opened, because a submit that was sent and cut off may already be billed. When retries run out after the submit, the job fails with `request failed after N attempts: <reason>` and the service adds no retry, while a submit that never connected fails with `request failed: <reason>` and `runner.networkRetries` can run the job again.
- [Visible] [Platform] **Jobs interrupted by an internet outage now run again instead of staying failed.** When a job fails with a lost-connection error, augurd runs the same request on the same route as a new job, up to `runner.networkRetries` times (Network outage retries, default 10, 0 turns it off), waiting 10, 20, 40, then 60 seconds between attempts. Jobs with `write` or `full` tools retry only if they left no answer and no recorded change. API jobs also retry a dropped connection inside the job, up to 10 requests within the job's `timeoutS`.
- [Visible] [Platform] **The service starts in a few seconds again instead of several minutes.** After the change feed landed, the job ledger's startup re-check read each job's last change through the wrong database index and scanned tens of thousands of rows per job, so a ledger of about 4,000 jobs took around 3.5 minutes to start. During that window the desktop app tried to restart the service, the restarts hit the database lock and exited, and every `augur` command, MCP tool, and dispatch call failed with "The service is not running" for several minutes. The lookup and the remote-refresh delete now use the per-job index, and each check takes well under a millisecond per job.
- [Visible] [Security] **A renewed sign-in on Linux is no longer lost when the Secret Service refuses saves.** Augur used to check only that the Secret Service could be read. An uninitialized or locked Secret Service could answer reads but refuse saves, so saving a renewed sign-in failed after the old refresh token was already spent, the new token was lost, and the user had to sign in again. An old Secret Service entry could also hide a newer value saved in the file. Augur now tests the Secret Service by saving, reading back, and removing a throwaway value. If the service refuses saves, or a save fails later, Augur saves to the file only the user can read and reads that file first until the service accepts saves, so a stale Secret Service entry no longer hides a newer one. If saving a renewed sign-in fails for any reason, Augur keeps the renewed session in memory and tries the save again at the next renewal, though a restart before a successful save still loses it.
- [Visible] [Platform] **Codex jobs that finish their turn but leave processes running now end on their own.** A Codex job whose worker left dev servers running could print turn.completed, write its answer, and still never end, sitting flagged as stalled until someone cancelled it by hand. If the Codex process is still running 15 seconds after the turn-completed event, Augur now ends the job's process tree, records the job as exited with code 0, and adds a note to its events.
- [Visible] [UI] **The status line now marks stale Claude usage.** When Claude's usage read is flagged stale, `augur status` and the line the Claude Code and Claude Desktop mod writes add the word `stale` after Claude's session and weekly numbers, and `augur status` raises its level to warn. Before, only other providers showed `stale`, so a stale Claude read looked current unless the whole usage file was more than 15 minutes old.
- [Visible] [Alerts] **A failed job that failover already moved to another route no longer raises a `job.failed` alert.** Before this fix, a provider limit such as a ChatGPT deep research rate limit (exit 70) raised a failure alert even when the next route finished the work, so one limit could send a burst of alerts to the webhook. A job with a retry (`retriedAs`) now stays quiet, and the retry alerts if it fails too, so the last failed job in a failover chain raises the alert. Stalled and over-usual-time alerts and the one-hour freshness rule are unchanged.
- [Visible] [Platform] **Chat-mode API jobs that hit their output limit now fail with a reason.** A job that stops at stop_reason max_tokens or finish_reason length fails with "output limit reached", naming the output token count and the route's maxTokens option, instead of completing with a cut-off or empty answer.
- [Internal] [Platform] **Jobs with short time limits no longer count a single scheduler tick as activity.** The job activity check now needs at least 50 ms of CPU growth between two looks in addition to 2 percent of elapsed time, so one 15 ms tick inside the 750 ms look used for a 3 second timeout no longer keeps a job running past its limit and failing two Windows supervisor timeout tests. Looks at the normal 15 second interval are unchanged because 2 percent of that is already 300 ms.
- [Visible] [Providers] **Signing in to OpenAI now completes for accounts without billing permission.** The sign-in window used to stay open on the billing page's Not Available message. It now closes, and the OpenAI API card notes that the account cannot read organization billing.
- [Visible] [Alerts] **A healthy job that prints nothing until it finishes, such as a Grok job, is no longer flagged as stalled.** Augur now counts a job as active while its processes use the processor, move at least 64 KB of disk or network data, or start new processes, so these jobs stop sending a stall alert on nearly every run. A job with no output and no process activity is still flagged after `stallMinutes`.
- [Visible] [Providers] **Example image routes saved without a Model no longer stop with "route option model is required".** An `images` route with an empty Model now takes its model from the route's label, and a Model you set still wins.
- [Visible] [Platform] **Sandboxed jobs no longer copy Rust or Maven build output into the workspace.** The copy skips a `target` folder that sits next to a `Cargo.toml` or `pom.xml`. Augur also checks the working directory at submit time and refuses one over 20000 files or 512 MB with a bad_request asking for a smaller `cwd`, before any job exists or the service stalls on the copy.
- [Visible] [Platform] The prose queue no longer fails every item with "cwd may not be inside the service data folder." Each prose group now runs in an `augur-prose-scratch` folder under the operating system's temporary folder, which is deleted when the group finishes, and items that failed before can be requeued and run.
- [Visible] [Platform] A route's parallel limit is now counted per provider and model id, so two routes whose policy labels name the same model share one limit instead of getting one each. A cap keyed by provider/id, such as caps."openai/gpt-x", now holds across every label for that model.
- [Visible] [Platform] `augur pick --named <model>` and `augur pick-preview --named <model>` now read the model name after the flag, where before they took `--named` as a switch with no value, ignored the model, and left an ask-first model such as `xai/grok` refused even when named. `--named=<model>` works as it did before, and `augur run --named` is unchanged and stays a switch.

### Removed

- [Visible] [Platform] Removed the `mcode-sbx` and `opencode-sbx` adapters, which ran a harness inside a Docker sandbox, along with the route options `sandbox`, `sbx`, `sbxPrefixJson`, the sandbox form of `workRoot`, and the OpenCode `host` pin option. A route that still names either adapter no longer loads, so point it at `mcode-exec` (MiniMax Code on the host, in a copy of the job folder) or `hermes-exec` (Hermes Agent), and drop both ids from the `adapters` list in the service config.
