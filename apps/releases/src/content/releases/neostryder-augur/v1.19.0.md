### Added

- [Visible] [Platform] `augur jobs` lists ledger metadata scoped to the current session by default, with filters, counts, paging, refresh, and a watch that reconnects; the legacy execution filters still work.
- [Visible] [Platform] `augur job` shows a job's ledger attribution, summary source, times, usage, history, and chain links. Local execution commands accept qualified local ids and reject remote ids.
- [Visible] [Alerts] `augur nodes` reports node polling and reachability, and `augur alerts` lists persisted job alert events with time filters. Usage alerts can still be dismissed.
- [Visible] [Platform] MCP ledger queries support session scope, filters, paging, and change cursors. MCP also has read-only tools for counts, nodes, and alerts, and its job details contain metadata only.
- [Visible] [Platform] Replays and backlog releases carry job stamps. CLI and MCP session stamps fall back to the host session id.
- [Visible] [Alerts] Job webhooks can send the Cresset event format, selected with the Webhook payload format setting in the app and the terminal.
- [Visible] [UI] The Jobs pages in the desktop app, the service-served PWA, and the terminal show ledger metadata, session scopes, filters, paging, and node health.
- [Visible] [Alerts] Job alerts have editable rules, desktop notifications that link to the job, a rotating JSONL outbox, optional HTTPS webhooks, and durable delivery receipts.
- [Visible] [Platform] **Laya can copy adapters to more than one machine.** `syncHosts` in `~/.augur/laya.json` lists more `user@host` targets alongside `syncHost`. A string entry receives the adapters, the registry, and the training row files, and an entry `{"host": "user@host", "rows": false}` receives the adapters and the registry only. `python packages/laya/src/sync.py push` copies to each host in order and reports each host separately, and a host that does not answer does not stop the others or leave a half-written registry. `status` prints the same per-host report, `pull` reads rows from the first host that receives them, and `--host` limits any of the three commands to one host. `push` and `pull` exit 1 after trying every host when any host failed. `push` now prints one JSON object, `{"hosts": [...]}`, even for a single host. Each sync host also joins the Laya pool as a failover server.
- [Visible] [Providers] **Retry on failure now also retries a job when the provider says its free allowance is used up, and a read-only job whose reply never arrived in time or whose browser connection was lost.** A used-up allowance counts as a provider limit, like a rate limit or quota message. A job with tools `write` or `full` is not retried after a missed reply or a lost browser, because it may already have changed files.
- [Visible] [Platform] The service records job attribution and summaries, receives job events from each node, and serves ledger queries and replayable watches. CLI runs accept session, title, origin, and summary flags. Full job metadata stays in the ledger for 90 days by default, after which finished jobs are compacted to summary rows.
- [Internal] [Alerts] The ledger persists stalled, failed, and duration alert events behind a sink interface. The duration rule does not fire until eight jobs have completed on the same route, node, and work kind.
- [Visible] [Platform] **Another program on the same machine can free Laya's video memory with `POST /yield`.** The server drops its checkpoints and adapters from video memory and empties the CUDA cache, and the next /v1/systemone request loads them again. Cogitator sends it before refusing a large model load for lack of video memory. The route serves loopback requests only and answers 403 to any request with an Origin header.
- [Visible] [Platform] **Windows updates no longer wait for or interrupt running jobs.** The installer stops the service with `augur service stop --keep-jobs`, which ends only leftover MCP server processes, then moves `augur-node.exe` and `jobhost.exe` aside so each running job keeps the old program until it ends while the new service carries on with it. If the installed command does not know `--keep-jobs` or the files cannot be moved, the installer waits for jobs to finish as before, and if that also fails it stops without changing anything. `augur service stop` accepts at most one of `--keep-jobs`, `--if-idle`, or `--wait`, and with `--json` it lists the ended process ids in `killedPids`.
- [Visible] [UI] **The Jobs page, the terminal Jobs tab, and `augur jobs` show each live job's last activity and a stalled marker.** The activity line sums up the job's latest output in at most 120 characters, such as the command a model is running, and a job is stalled when its process is alive but has produced no output for `stallMinutes` (10 by default, minimum 1, set in Service settings or `augur config`). Augur only flags a stalled job and never cancels it, and the new Running filter (`augur jobs --running`) lists only queued, awaiting-approval, running, and cancelling jobs.
- [Visible] [Platform] **The Claude Code plugin shows live Augur jobs.** The status line adds the live job count with stalled jobs, such as `3 jobs (1 stalled)`, and the `augur-jobs` pane lists one row per job with stalled jobs first. The pane opens the first time a live job appears in a session, and `/augur-jobs` opens it again. The service writes `jobs-live.json` in `~/.augur` for the plugin, with up to 50 live jobs and never the prompt or the answer.
- [Visible] [Platform] **`augur replay` and the `augur_replay` MCP tool run a finished job again on another route.** The new job uses the original's saved prompt and job settings, passes the same checks as any request, and shows "replay of <id>" in `augur job`, `augur jobs`, `augur_job`, and `augur_jobs`. A job cannot be replayed if it is unfinished, has no saved prompt, or used input files or a response schema. Agents can call replay with their own token, and `augur job <id>` is the same as `augur status <id>`.
- [Visible] [Platform] **One job can keep its prompt and input files with `--keep-prompt` on `augur run` or `persistPrompt` in `augur_run`, whatever the Keep prompts setting says.** `persistPrompt` false discards them even when the setting is on, and leaving it out follows the setting. A kept prompt is deleted with its job at retention (`retentionDays`, 30 by default).
- [Visible] [Platform] **A busy Laya server can pass /v1/systemone requests to other Laya servers listed in `LAYA_FAILOVER_URLS`.** While a game runs or other programs use the card, the request goes to the first listed server whose /load reports ready and not busy, and the answer comes back with an `x-laya-served-by` header naming that server. Forwarded requests carry `x-laya-forwarded: 1` and are never forwarded again, and only the content type and that header are sent on. `LAYA_FAILOVER_PROBE_S` (default 2) and `LAYA_FAILOVER_TIMEOUT_S` (default 120) set the probe and request timeouts in seconds, and an unset or empty list keeps the old 503 with Retry-After.

### Changed

- [Internal] [Providers] **The `window destroyed` line in `signin.log` now records the sign-in window's last address and whether a close was requested.** `last_host=` and `last_path=` hold the last address the watcher saw, without the query string or fragment, so a page that closes in under one watcher check is not captured. `close_requested=` is true when a close request came before the window was destroyed, and this tells a person closing the window apart from the page closing itself.

### Fixed

- [Visible] [Platform] When a node cursor expires, Augur resumes polling and shows a persistent history gap. Unfinished jobs with missing events appear as node-lost until a newer event arrives.
- [Visible] [Platform] **`augur wait` and `augur run --wait` keep waiting when the service restarts.** They used to exit with "The service is not running (ENOENT)" and a success-looking code while the job kept running. They now retry until the service returns and note the outage on stderr.
- [Internal] [Platform] **The Laya server's model resolver accepts the resolve function Laya 0.4 passes in.** Laya 0.3 calls the same function with the model name alone. A name that starts with `laya:` is returned unchanged, and any other name is forwarded to the stock resolver with the extra arguments.
- [Visible] [Providers] **A sign-in window that closes by itself within seconds of opening now reopens once.** Before, the provider's reading stayed missing with no message until you tried again. A window that closes within 90 seconds, before it reaches another host and without a signed-in reading, reopens one second later, and the settings and setup screens now show a notice naming the site whenever a sign-in window closes without a signed-in reading.
- [Visible] [Platform] **The game check and idle unload keep working when Laya cannot read the graphics card.** Before this fix, a missing `nvidia-ml-py` package turned off every load-gate protection, so Laya stayed in video memory while a game ran and the game stuttered. Now only the GPU-use and video-memory readings are missing, and GET /load shows the error in a new `sample_error` field. The README install command now installs `nvidia-ml-py` alongside `laya`.
